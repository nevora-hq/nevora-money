# 記事データ

記事Markdownの**一次情報源**。`サイト運営\サイト本体\content\articles` は
`scripts\sync-content.js` がここから毎ビルド再生成するコピーなので、編集は必ずこちら側で行う
(詳細は `docs\CONTRIBUTING.md` 1節)。

| フォルダ | 用途 |
|---|---|
| `キーワード調査` | keyword-researcher の調査結果 |
| `作成中` | 作りかけの記事の作業フォルダ(記事ごと。企画書・原稿・確認メモ・判定の記録・画像のプロンプト)。サイトには出ない。**中身は git に入れない**(`.gitignore` で無視。`.gitkeep` だけ残す)。公開したら、その記事のフォルダを消す(あとで要るもの〔画像のプロンプトなど〕は、消す前に報告へ出す。予約投稿の記事は、公開待ちに置いた回の報告に出し、公開されたことを次の作業の回で確かめたあとに消す) |
| `公開待ち` | 判定を通った、公開する版の1ファイルだけを置く。公開キュー(`npm run queue` が扱う)が、公開時刻の到来分を公開済みへ移す。サイトには出ない |
| `公開済み` | サイトに出ている記事の全部。公開待ちから移すのは公開の処理(公開キュー)だけ。公開済みの記事を直すときは、ここの同じファイルを直す |
| `振り返り` | 公開後のマーケターによる分析メモ |
| `非公開アーカイブ` | 取り下げた記事の退避先。サイトには出さない |

**各フォルダの `.gitkeep` は削除しないこと。** 空フォルダはGitが追跡しないため、
これが無いとクローン直後にフォルダごと存在しなくなり、
`npm run sync-content` が警告を出し、GitHub Actions の item35-weekly が
`ls ../記事データ/公開済み` の時点で失敗する。
