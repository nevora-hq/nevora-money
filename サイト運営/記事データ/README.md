# 記事データ

記事Markdownの**一次情報源**。`サイト運営\サイト本体\content\articles` は
`scripts\sync-content.js` がここから毎ビルド再生成するコピーなので、編集は必ずこちら側で行う
(詳細は `docs\CONTRIBUTING.md` 1節)。

| フォルダ | 用途 |
|---|---|
| `キーワード調査` | keyword-researcher の調査結果 |
| `確定稿` | 編集長承認済み・未公開の記事。サイトには掲載される |
| `公開待ち` | 公開キュー(`npm run queue` が扱う。公開時刻の到来分を確定稿へ移す) |
| `公開済み` | 公開後に確定稿から移動したもの。サイト掲載は継続する |
| `振り返り` | 公開後のマーケターによる分析メモ |
| `非公開アーカイブ` | 取り下げた記事の退避先。サイトには出さない |

**各フォルダの `.gitkeep` は削除しないこと。** 空フォルダはGitが追跡しないため、
これが無いとクローン直後にフォルダごと存在しなくなり、
`npm run sync-content` が警告を出し、GitHub Actions の item35-weekly が
`ls ../記事データ/確定稿` の時点で失敗する。
