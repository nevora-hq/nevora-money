# 出典フォーマット仕様(sources)

フェーズ2(2026-08-10)で新設。記事frontmatterの `sources` フィールドで出典を構造化して管理する仕様。実装は `lib/posts.js`(`normalizeSources`)・`components/ArticleSources.js`。

## 背景

過去の監査で、多数の記事が出典として「トップページURL」「まとめメディアのランキング記事」のみを引用しており、一次情報(公的機関・学会・論文・業界団体・メーカー公式)が不足していることが判明した。従来の出典は本文末尾の「## 出典一覧」見出し+自由形式Markdownリンクのみで、一次/二次の区別・URLの深さ・編集部独自調査であることの明示が構造化されていなかった。

この仕様は、B3(出典の弱さ)の再発をコード側で検知しやすくすることと、フェーズ7(記事自動生成プロンプト改訂)で新規記事が最初から一定水準の出典を持つことを目的とする。

## frontmatterスキーマ

```yaml
sources:
  - label: "厚生労働省 e-ヘルスネット"
    url: "https://www.e-healthnet.mhlw.go.jp/information/heart/y-002.html"
    type: "primary"
  - label: "◯◯クリニック公式コラム"
    url: "https://example-clinic.jp/column/xxxx"
    type: "secondary"
  - label: "編集部調査"
    type: "editorial"
    surveyN: 20
    surveyMethod: "アンケート(NEVORA読者)"
    surveyDate: "2026-08"
```

### フィールド

| フィールド | 必須 | 説明 |
|---|---|---|
| `label` | 必須 | 出典の表示名(サイト名・調査名など) |
| `type` | 必須 | `primary`(一次情報) / `secondary`(二次情報) / `editorial`(編集部調査)のいずれか |
| `url` | `primary`/`secondary`で必須 | 該当ページの**深いURL**(トップページのみは警告対象。判定は「pathnameが空または`/`のみ」の簡易チェック) |
| `surveyN` | `editorial`で必須 | 調査のn数(サンプル数) |
| `surveyMethod` | `editorial`で必須 | 調査方法(例:「アンケート」「編集部内ヒアリング」) |
| `surveyDate` | `editorial`で必須 | 実施時期(例:「2026-08」) |

### type の使い分け

- **primary(一次情報)**: 公的機関・学会・論文・業界団体・メーカー公式など、情報の一次発信元。
- **secondary(二次情報)**: 経済メディア・金融機関のコラム等、一次情報を紹介・解説している情報源。一次情報が別途無い場合の補助として使う。
- **editorial(編集部調査)**: NEVORA編集部が独自に行った調査・ヒアリング・試算。フェーズ1指示7項の方針により、非公式調査であっても「編集部調査(n数・調査方法・実施時期を明記)」として正直にラベリングすれば独自データとしての強みになる、という考え方に基づく。n数等が記録に無く明記できない場合は、この`sources`に載せず本文中で「筆者調べ」等の表現も使わない(削除するか、明記できる形に調べ直す)。

**primary/secondaryの区分基準の補足(フェーズ5、2026-08-11追加)**: 「本文中で直接引用しているかどうか」と「一次情報か二次情報か」は独立した属性であり、混同しないこと。一次情報とは情報の発生源(公的機関・業界団体・金融機関の公式発表・編集部が自ら実施した調査)を指す。経済メディア・比較サイト等の編集メディアは、本文中で直接引用していても情報の発生源ではないためsecondaryのままである。

## バリデーション(ビルド時警告)

`lib/posts.js` の `normalizeSources` が以下をチェックし、違反時は `next build`/`next dev` のログに `console.warn` を出す(**ビルドは失敗させない**。記事データはMarkdownで人手管理のため、軽微な入力漏れでビルド全体を止めると運用の障害になるため)。

- `label` が空
- `type` が `primary`/`secondary`/`editorial` 以外(未指定含む)→ `secondary` 扱いにフォールバック
- `primary`/`secondary` で `url` が空、またはトップページ相当(浅いURL)
- `editorial` で `surveyN` / `surveyMethod` / `surveyDate` のいずれかが空

## 表示

`components/ArticleSources.js` が `post.sources` を受け取り、記事末尾(悩みチップの後、参考情報の明記の前)に「出典」見出し+リストとして描画する。`type` ごとにバッジ(一次情報/二次情報/編集部調査)を表示する。`sources` が空配列の記事ではコンポーネントは何も描画しない。

## 既存記事(本文「## 出典」セクション)との関係

**一斉移行はしない。** 全124記事のうち、`sources` が設定されているのは今後フェーズ5・通常の記事修正のついでに移行した記事のみで、それ以外の記事は従来通り本文中の「## 出典」見出し+Markdownリンクがそのまま表示される(後方互換)。

- `sources` が設定された記事は、本文側の「## 出典」セクションを**削除すること**(残すと出典が二重表示される)。
- 削除を忘れた場合、`lib/posts.js` の `getPostBySlug` が `sources` と本文の `## 出典`/`### 出典` 見出しの共存をビルド時に検知し、`console.warn` で警告する(自動では本文側を削除しない。正規表現によるHTML分割はB1/B2と同種の不具合を招くリスクがあるため)。

## 出典の検証基準(フェーズ5標準ルール、2026-08-10確定)

出典URLを追加・移行する際は、次の2段階を必ず両方満たすこと。**「URLが実在する」ことと「そのURLが記述内容の根拠になる」ことは別物であり、前者だけでは出典として不十分。**

1. **実在確認**: URLが実在し、リンク切れでないこと(WebSearch等で確認)。
2. **裏付け確認**: そのページの内容が、記事本文の当該記述を実際に裏付けているか(組織のトップページ・関連ページというだけで、記述内容そのものには触れていない、ということがないか)を確認すること。

裏付け確認の結果に応じて、以下のいずれかで対応する。

- **完全に裏付ける** → そのまま`primary`/`secondary`として採用。
- **部分的にしか裏付けない**(例:出典1件で2つの主張をカバーしようとしていたが、片方しか支持しない) → 出典を分割し、それぞれが実際に裏付ける範囲だけをラベルに明記する。
- **裏付けを直接確認できない**(検索がJavaScript駆動で結果を直接確認できない等) → `primary`として扱わず`secondary`に格下げし、ラベルに確認状況(例:「要人手検索確認」)を明記する。実在すら確認できない場合は出典として使わない。

この基準は、`2026-08-05_アゼライン酸とは.md`の出典移行(下記)で実際に運用し、2件の修正(出典分割・secondary格下げ)につながった。フェーズ5の出典差し替え作業全体で標準として適用すること。

## 移行済みの見本記事

`サイト運営\記事データ\確定稿\2026-08-05_アゼライン酸とは.md` を最初の移行事例として実装・検証済み(2026-08-10)。フェーズ0監査で「良い実装例」とされていた記事で、本文の「## 出典」を`sources`スキーマへ移行し、本文側の見出しは削除した。フェーズ5で他記事を移行する際のテンプレートとして参照すること。

移行時、上記の検証基準に沿って元の出典4件をWebSearch/WebFetchで再検証した結果、2点の修正が必要だった。

- 元の出典は「米国FDA承認情報:Finacea(azelaic acid)添付文書」1件で本文の「ニキビ・酒さの治療に使われてきました」を裏付けようとしていたが、Finacea(ゲル15%)の適応症は酒さ(rosacea)のみで、ニキビ(acne vulgaris)への適応はラベルに明記されていなかった。ニキビに適応があるのは別製品のAzelex(クリーム20%)のため、**Finacea(酒さ)とAzelex(ニキビ)の2件に分割**して、それぞれが実際に裏付ける範囲を明示した。
- 「日本化粧品工業連合会 化粧品成分表示名称リスト」は、公式サイト(jcia.org)の検索がJavaScript駆動でWebFetchから直接結果を確認できず、「アゼライン酸」がリストに含まれることを一次情報源で直接確認できなかった(第三者の成分データベースでは該当する成分番号が確認できたのみ)。**未確認のまま`primary`として掲載せず、`secondary`に格下げし、ラベルに「要人手検索確認」と明記**した。

## 移行方針

- フェーズ5(出典の弱い記事、約20件)の差し替え作業で、対象記事から順次この形式に移行する。
- フェーズ5対象外の記事は、期限を設けず、内容修正の機会があるついでに移行する。
- フェーズ6(記事自動生成プロンプト改訂)以降の新規記事は、原則として `sources` を必須とする。
