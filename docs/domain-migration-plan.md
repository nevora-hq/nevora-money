# 独自ドメイン移行 手順書(【未確定: 独自ドメイン】)

性質: **手順書・チェックリストのみ。移行の実施はフェーズ5・6完了後。** このファイルに沿って作業する際は、各ステップ完了時にチェックを入れて更新すること。

## 前提

- 新ドメイン: 【未確定: 独自ドメイン】
- レジストラ: 【未確定: レジストラ】(以下のお名前.com固有の画面・手順は、レジストラがお名前.comの場合の手順。他のレジストラでは読み替える)
- ホスティング: **Vercel**(現行のまま)。レンタルサーバーは契約していない
- 現行の公開URL: `NEXT_PUBLIC_SITE_URL`環境変数(Vercelダッシュボードで設定、`.env.example`参照)で管理されている `https://nevora-money.vercel.app`

## 1. 移行実施の前提条件チェック

- [ ] **お名前.comからのドメイン情報認証メールに対応済みであること**
  - ドメイン取得時、および登録者情報(Whois情報)を変更した際に、お名前.comから「[お名前.com] WHOIS情報の内容確認のお願い」といった件名のメールが登録メールアドレスに届く。これはICANNのルールに基づく**メールアドレス有効性確認**であり、一定期限内(通常15日)に確認手続きをしないと**ドメインの利用が制限される**(名前解決が止まる=サイトが表示されなくなる)。
  - **件名の見分け方**: お名前.comは販促メール(セール告知・他サービスの案内)が非常に多いため、認証メールを埋もれさせやすい。件名に「WHOIS」「確認」「認証」「重要」といった語が入っているものを優先的に確認する。
  - **差出人名の見分け方**: 認証メールは、差出人名が「お名前.com」ではなく**「verification-noreply」名義**で届くことがある。差出人名だけで「お名前.com公式ではない」と判断して見落とさないよう注意する。件名(WHOIS/確認/認証等のキーワード)を優先的な手がかりにすること。
  - 迷惑メールフォルダに振り分けられていないかも必ず確認する。
- [ ] **お名前.com Naviでドメインのステータスが「有効」であることを確認**
- [ ] **自動更新設定の確認**(更新忘れによるドメイン失効を防ぐため。お名前.com Navi内「ドメイン設定」→該当ドメインの自動更新設定を確認し、有効になっていることを確認する)
- [ ] **Whois情報公開代行が有効になっているかの確認**(個人運営の場合、登録者の個人情報がWhois検索で公開されないよう、代行サービスが有効か確認する。無効だと個人情報がインターネット上に公開された状態になる)
- [ ] **不要なオプションを誤って契約していないかの確認**(お名前.comは申込み時に有料オプション(サーバー契約・SSL証明書・メールサービス等)が同時カート追加される導線が多い。今回はVercelホスティングでレンタルサーバーは不要なため、意図しないサーバー契約等が入っていないか、契約中サービス一覧で確認する)
  - **ドメインプロテクションの勧誘に注意**: DNSレコード設定の確定前に「ドメインプロテクション」等の有料オプション加入を勧める確認ポップアップが表示されることがある。**青色の強調ボタンが有料契約側**になっているUIのため、不要な場合は誤って青いボタンを押さず「設定しない」等の選択肢を選ぶこと。

## 2. Vercel側のカスタムドメイン追加とDNS設定

### 2-1. Vercel側の作業

- [ ] Vercelダッシュボード → 対象プロジェクト → Settings → Domains で `【未確定: 独自ドメイン】`(および必要に応じて`www.【未確定: 独自ドメイン】`)を追加
- [ ] Vercelが表示する推奨DNS設定(通常は以下のいずれか)を控える
  - ルートドメイン(`【未確定: 独自ドメイン】`)には **Aレコード**(Vercelが指定するIPアドレス、例: `76.76.21.21`)
  - `www`サブドメインには **CNAMEレコード**(`cname.vercel-dns.com`など、Vercelが表示する値をそのまま使う)
  - どちらをルートにするか(`【未確定: 独自ドメイン】` / `www.【未確定: 独自ドメイン】`)は事前に決めておき、もう一方からのリダイレクトをVercel側で設定する

### 2-2. お名前.com Navi側の作業

- [ ] お名前.com Navi → ドメイン設定 → DNS関連機能設定 → 該当ドメインの「DNSレコード設定を利用する」を選択
- [ ] 以下のいずれかの方法でVercelに向ける
  - **方法A: ネームサーバー変更**(Vercelにネームサーバー管理ごと委譲する場合)
  - **方法B: DNSレコード設定**(お名前.com Naviの「DNSレコード設定」画面で、2-1で控えたA/CNAMEレコードをそのまま入力して保存する)
- [ ] 設定後、DNS反映には最大72時間かかる場合がある(通常は数十分〜数時間程度のことが多い)。反映待ちの間はVercel側のDomainsタブでステータスを随時確認する

## 3. `NEXT_PUBLIC_SITE_URL`環境変数の変更

- [ ] Vercelダッシュボード → 対象プロジェクト → Settings → Environment Variables で `NEXT_PUBLIC_SITE_URL` を `https://【未確定: 独自ドメイン】`(末尾スラッシュなし)に更新する(Production環境向けの値)
- [ ] 変更後、再デプロイ(Redeploy)を行わないと反映されない点に注意(Vercelの環境変数はビルド時に埋め込まれるため)
- [ ] **例外がないかの最終確認**: `NEXT_PUBLIC_SITE_URL`はcanonical・OGP・構造化データの絶対URL生成に使われ、コード上は`components/Layout.js`が参照元として一元化されている。移行前にコードベース内を検索し、`about.js`・`sitemap.xml.js`・`category/index.js`・`posts/[slug].js`・`worry/[slug].js`・`worry/index.js`・`category/[name].js`・`robots.txt.js`・`next.config.js`などが`NEXT_PUBLIC_SITE_URL`経由の一元管理になっており、ハードコードされた`vercel.app`等のドメイン文字列がサイト本体側コードに存在しないことを確認する(`lib/siteLinks.js`内のURLは他のNEVORAサイト自身のドメインであり、当サイトの移行とは無関係)。**移行時に個別ファイルを書き換える必要はなく、環境変数の変更のみでよい**
- [ ] `next.config.js`は`NEXT_PUBLIC_SITE_URL`が未設定だと本番ビルド(`next build`)自体をエラーで止める仕様になっている(canonical/OGP出力漏れを検知しにくい問題への対策として、フェーズ4以前に実装済み)。**環境変数の設定を忘れた場合はビルドが失敗するため、移行時に気づきやすい設計になっている**
- [ ] 一方、`pages/sitemap.xml.js`は`NEXT_PUBLIC_SITE_URL`が未設定でもリクエストのホスト名から自動的にURLを補う設計のため、**この項目だけは環境変数を変更し忘れても壊れて見えない**。sitemapのURLが新ドメインになっているか個別に確認すること(6節参照)

## 4. 旧URL → 新URLのリダイレクト確認

- [ ] Vercelはカスタムドメイン追加時、旧URL(`https://nevora-money.vercel.app`)から新ドメインへの自動リダイレクトは**行わない**(Vercelの`.vercel.app`ドメインは常にプロジェクトの現在のデプロイに直接アクセスできる形で残り続ける)。恒久的な301リダイレクトが必要な場合は、Vercelプロジェクト設定の「Domains」で旧ドメインを「Redirect to (新ドメイン)」として明示的に設定する
- [ ] 301リダイレクトを設定した場合、以下の代表的なパスで実際にリダイレクトが機能するか検証する
  - [ ] トップページ(`/`)
  - [ ] 記事ページ(`/posts/[slug]`を数件)
  - [ ] カテゴリページ(`/category/[name]`)
  - [ ] 悩みページ(`/worry/[slug]`)
  - [ ] `/sitemap.xml`・`/robots.txt`
- [ ] リダイレクトのステータスコードが`301`(恒久的)であり`302`(一時的)でないことを、ブラウザの開発者ツールまたは`curl -I`で確認する

## 5. Google Search Console

- [ ] 新ドメイン用のプロパティを追加する。**ドメインプロパティ(`【未確定: 独自ドメイン】`、DNS認証)を推奨**(URLプレフィックス方式より、http/https・www有無をまとめて1つのプロパティで管理できるため)
- [ ] 所有権確認: ドメインプロパティの場合はDNSのTXTレコード追加で確認する(お名前.com Navi側のDNSレコード設定で追加。2節のA/CNAMEレコードと同じ画面で追加できる)
- [ ] 現行サイトは`NEXT_PUBLIC_GSC_VERIFICATION`環境変数によるmetaタグ確認方式も実装済み(`.env.example`参照)。ドメインプロパティ(DNS方式)を使う場合はこの環境変数は不要だが、URLプレフィックス方式を併用する場合は新ドメイン用の確認コードを取得しVercelの環境変数に設定する
- [ ] サイトマップ再送信: Search Console → サイトマップ → `https://【未確定: 独自ドメイン】/sitemap.xml`を送信する。ステータスが「成功しました」になること、sitemap内の全URLが新ドメインであることを確認する
- [ ] 移行後しばらくは「以前のプロパティ」の旧`.vercel.app`側もSearch Console上に残しておき、旧URLのインデックス状況(徐々に新URLへ差し替わっていくか)を数週間モニタリングする(継続監視事項)

## 6. 移行後検証チェックリスト

- [ ] `https://【未確定: 独自ドメイン】/sitemap.xml`のURLが**すべて新ドメイン**になっているか(3節の通り、`NEXT_PUBLIC_SITE_URL`未設定でもリクエストのホスト名から自動補完されるため、正しいホストでアクセスしていれば通常は問題ないが、念のため確認)
- [ ] 記事ページのcanonicalタグ(`<link rel="canonical">`)が新ドメインを指しているか(数記事をブラウザの「ページのソースを表示」で確認)
- [ ] OGP(`og:url`・`og:image`)が新ドメインの絶対URLになっているか(SNSシェアデバッグツール等で確認)
- [ ] 構造化データ(JSON-LD、Article/BreadcrumbList/WebSite)内のURLが新ドメインになっているか(Google の「リッチリザルト テスト」で確認)
- [ ] `robots.txt`が新ドメインのsitemap URLを参照しているか
- [ ] `public/ads.txt`が新ドメインでもそのままアクセスできるか(`https://【未確定: 独自ドメイン】/ads.txt`。Next.jsの`public/`配下はドメインに依存せず配信されるため、通常は追加作業不要。`docs/adsense-checklist.md`参照)
- [ ] 旧URLからのリダイレクトが機能しているか(4節の検証結果を再確認)
- [ ] 主要ページ(トップ・記事・カテゴリ一覧・悩み一覧・検索・about・privacy-policy・terms・contact)が新ドメインで正常に表示されるか一通り目視確認する
- [ ] Vercel側の環境変数(`NEXT_PUBLIC_SITE_URL`・`NEXT_PUBLIC_GSC_VERIFICATION`・`NEXT_PUBLIC_ADSENSE_CLIENT`・`NEXT_PUBLIC_GA_MEASUREMENT_ID`)がすべて新ドメイン向けの値になっているか再点検する

## 7. 切り戻し手順

移行後に致命的な問題(サイトが表示されない、大量の404、決済・お問い合わせ機能の不具合等)が発生した場合の切り戻し方針。

### 切り戻しを判断する基準

- 新ドメインでサイトが**完全に表示不能**な状態が発生し、原因がDNS反映待ち(通常想定内)ではなく設定ミスと判断できる場合
- 主要ページ(トップ・記事・お問い合わせ)が広範囲にわたって500エラー・404エラーを返す場合
- 上記が発生し、かつVercel側の設定修正・再デプロイでは即座に解決できないと判断した場合

### 切り戻し手順

1. Vercelプロジェクト設定 → Domains で、旧ドメイン(`nevora-money.vercel.app`)へのアクセスが引き続き機能していることを確認する(Vercelの`.vercel.app`ドメインはカスタムドメイン追加後も無効化されないため、通常は追加作業なしでアクセス可能なはず)
2. お名前.com Navi側のDNSレコードを、移行前の設定に戻す(2節で変更したA/CNAMEレコードを削除、または元の値に戻す)。**DNSレコードは事前にスクリーンショット等で必ず記録しておくこと**
3. `NEXT_PUBLIC_SITE_URL`環境変数を旧URLに戻し、Vercelで再デプロイする
4. Google Search Consoleの新ドメインプロパティは削除せず残し、状況が落ち着いてから原因を切り分けて再移行する
5. DNS変更の巻き戻しも反映まで時間がかかる場合があるため、切り戻し完了まで旧URLと新URLの両方で状況を監視する
