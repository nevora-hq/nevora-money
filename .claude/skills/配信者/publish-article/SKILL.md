# 記事公開スキル(配信者)

> **【ルール本体は`.claude/agents/publisher.md`が正】** 詳細な手順・判定基準・出力フォーマットは`.claude/agents/publisher.md`を参照すること。**このファイルとpublisher.mdの記述が食い違った場合は、常にpublisher.mdを正としてこのファイル側を修正する。**

## 記事が公開される経路(新規記事の公開は束ねる側が行う)

新規記事の公開の仕方は、依頼者の「すぐ公開」の指定で分かれる(2026-10-12 依頼者の決定。正は `.claude/agents/publisher.md` の「記事が公開される経路」)。指定がある記事は、`publishAt` を今の時刻以前にして `記事データ\公開待ち\` に置き、push のあと `サイト運営\サイト本体` で、先に `git pull`(merge)で最新を取り込み、`npm run queue:release` を手元で実行し(期限の過ぎた別の予約記事も一緒に移るので、移ったファイルは全部 commit する。詳細は publisher.md)、`記事データ\公開済み\` へ移ったファイルだけをファイル名を指定して commit・push する。指定が無い記事(複数まとめて作る場合を含む)は予約投稿にし、`npm run queue` で時刻を割り振って公開待ちに置き、push の前に公開待ちの記事すべてに `publishAt` が入っていることを確かめ(入っていない記事は公開されないまま残る)、画像のプロンプトなどあとで要るものは公開待ちに置いた回の報告に出し、commit・push して終わる(公開は自動処理に任せ、待たず、手動でも実行しない)。pushでVercelが自動デプロイし、公開済みの記事がサイト・sitemapに出る。

このスキルの担当は、(a) 既に公開済みの記事に加えられた修正をサイトへ反映すること、(b) 公開後のPinterest追記・ピン画像作成 の2つである。新規記事の公開を依頼された場合は、「すぐ公開」の指定の有無を見て、上のア・イのとおりに行う。

## 公開ゲートについて

サイト本体に公開ゲート(`publish-gate.js`・台帳の指紋照合)は無い。台帳への記録や `publish-gate --check` は行わない。公開前の確認は、publisher.md の「公開前の必須確認」だけである。

## 反映の前提(ゲート、詳細はpublisher.md参照)

`記事データ\公開済み\`・`公開待ち\`配下の記事をcommit・pushする前に、`node scripts/verify-article.js "<対象記事の絶対パス>"` を必ず実行する。**目視での「合格しているはず」という推測でゲートを通さない。**

- 実行そのものは必須で、`overall=No`の記事は公開せず、直してから公開する(publisher.mdの「公開前の必須確認(ゲート)」節参照)。信頼性系ブロッキング違反(item10/11/12等)が公開済みの記事に見つかった場合は即時修正が原則、修正に時間を要する場合の非公開化は**必ずユーザー決裁を経る**(`docs/CONTRIBUTING.md` 26節(b))
- 実行結果のJSONは `docs/pipeline/verify/{slug}_{実行日 YYYY-MM-DD}.json` に保存する

## 反映の流れ(概要)

1. `git status` で `サイト運営\記事データ\公開済み\` 配下に未コミットの変更が無いか確認する
2. 変更があれば、内容(記事タイトル・変更概要)を報告に書いたうえで、確認を待たずに該当ファイルを明示的に指定して`git add`→`git commit`(記事タイトルを含むメッセージ)
3. `git push`の前に、依頼者の確認は取らない(2026-10-03 依頼者の決定)。公開の手順(最後の関門の表・公開前の必須確認)を満たしたら push する
4. push後、Vercel側の自動デプロイ完了を確認する(デプロイの反映を確かめる待ちとして最低5分待つ、`CLAUDE.md`のデプロイ運用ルール参照。これは記事の公開〔キューの実行〕を待つことではない)

## サイト未実装の場合

`サイト運営\サイト本体\`にNext.jsプロジェクトがまだ存在しない場合は、作業を中断し、`site-engineer`による最低限の実装を先に依頼するようユーザーに案内する。

## エラー時

git操作やビルドが失敗した場合、エラーメッセージをそのまま報告し、憶測で原因を断定しない。原因調査が必要な場合はincident-responderへの依頼を提案する。先行 commit で弾かれた場合の取り込み方は CLAUDE.md のデプロイ運用ルールのとおりにし、行ったことを報告する。
