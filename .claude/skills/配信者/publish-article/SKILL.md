# 記事公開スキル(配信者)

## 事前確認
1. `サイト運営\記事データ\確定稿\` にファイルがあるかGlobで確認する
2. ファイルがあれば中身をReadで確認し、タイトル・本文の要点をユーザーに提示する(誤字や法務リスクが残っていないか最終目視も行う。気になる点があれば公開前に報告する)
3. ファイルが無ければ「公開待ちの確定稿がありません」と報告して終了する

## 公開実行
1. 確定稿のMarkdownを `サイト運営\サイト本体\` 配下のcontentディレクトリ(サイト実装済みの場合)へコピー・配置する
2. `git add` → `git commit -m "記事タイトルを含むメッセージ"` を行う
3. `git push` の実行前に、必ずユーザーへ「このタイミングでサイトに公開してよいか」を確認する
4. push後、Vercel側の自動デプロイが開始される旨を伝える(デプロイURLが分かれば案内する)
5. 公開が完了した確定稿ファイルは `サイト運営\記事データ\公開済み\` へ移動する

## サイト未実装の場合
- `サイト運営\サイト本体\` にNext.jsプロジェクトがまだ存在しない場合は、公開作業を中断し、`site-engineer` による最低限の実装(記事ページ等)を先に依頼するようユーザーに案内する

## エラー時
- git操作やビルドが失敗した場合、エラーメッセージをそのまま報告し、憶測で原因を断定しない。原因調査が必要な場合はincident-responderへの依頼を提案する
